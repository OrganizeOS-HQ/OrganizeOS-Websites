# Second comparison data (T59.6, measurement 22): R1 `a3bc7d8` against `<base>` `2a96a45`

Both builds were run afresh on 2026-11-26 and 2026-11-27: the seven record sets (19,477 records at each build) and
check 5's probes (83 probe runs at each build). The report is `../../p-records-task26-second.md`.

How the data was made:

- Drivers are copies of the first re-run's (`gdrive553.py`, `prun.sh`). Each set's batches ran in their own scratch
  directory (`native/zzacc-<set>-<batch>`, gap-fill in `zzacc-gap-fill`, which its engine names). The stall watchdog
  was 40 s. Every run at both builds ran under `timeout -s KILL 600` and resumed after a kill. All scratch
  directories are removed.
- Comparisons use `compare.py`'s field rules (`sig_engine`, `sig_case`). Two normalisations are applied:
  - the gap-fill image URL's port becomes `http://localhost:PORT/`, as in the first re-run;
  - a walk stop's `kms` (a duration in ms) is dropped, like `ms`. It changes no equal or different count
    (`completeness-with-kms.md` has the table without the drop). It only changes the count of records that
    differ from their earlier run (189 to 29 at the base).
